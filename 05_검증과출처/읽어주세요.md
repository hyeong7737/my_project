# 코드 출처와 완료 범위

## 코드 복사본

코드_복사목록.json에 원본 상대 경로, 복사본 상대 경로, SHA-256을 기록했다. 현재 통합 경로에 필요한 12개 운영 모듈을 원본 내용 그대로 복사했다. 이 파일들의 함수나 기본값은 정리 과정에서 수정하지 않았다.

모듈 안에 남아 있는 보조 기능은 코드에서 삭제하지 않고 설명에서 구분했다. 예를 들어 inverse_spectrum의 교대 투사는 통합 실행에서 ap_restarts=0으로 꺼져 있고, 지도 생성 보조 함수는 운영 탐색 단계가 아니다. 폐기된 블록 풀이·별도 BDD 실험·기준 경로 DP는 복사하지 않았다.

실행.py, 복사본_검증.py는 이 정리본을 위한 도구다. 정리본 생성 스크립트는 상위 연구프로그램/정리본_생성.py에 있으며, 재실행하면 문서와 코드 복사본을 갱신한다. 실행 도구와 별도로 추가한 공통 설명 파일은 유지한다.

## 검증

원본_83개_검증로그.txt는 원본 프로젝트의 83개 자동 검증 통과 기록이다. 이 수에는 과거 기능의 회귀 검사도 포함되며, 83개 모두가 새 알고리즘의 독립 성능 실험이라는 뜻은 아니다.

복사본_검증.py는 다음을 확인한다.

1. 복사한 12개 파일의 해시가 기록과 동일함.
2. 실제 import한 12개 모듈이 정리본 안의 파일임.
3. 복사본 통합 실행이 완료되고, 정확 스펙트럼 집합과 모든 최적 m이 원본 결과와 일치함.
4. 복원된 회로를 다시 읽으면 같은 지도와 m이 나옴.
5. 3노드 설명용 행렬의 trace·시간·회로 변환이 일치함.
6. SVG XML과 HTML 로컬 링크가 유효함.

결과는 복사본_검증결과.json이다. 원본 소스가 나중에 바뀌어도 이 복사본이 자동 갱신되지는 않는다. 재생성 후 검증을 다시 실행해야 한다.

## 완료한 것과 다음 단계

현재 명세의 지도 입력 → 스펙트럼 전체 생성 → 최소 시간 묶음 선택 → 정수 경로와 LC 회로 복원은 구현되어 있다. 정확성은 선언한 유한 영역과 자원 한도 안에서 해석해야 한다.

다음 단계는 사용자가 예고한 기존 알고리즘과의 비교 시뮬레이션과 프로젝트 결과 산출이다. 이번 정리 작업에서는 새 비교 프로그램이나 성능 우위 결론을 만들지 않았다. 대규모 시간복잡도 개선, 실물 LC 회로 실험, 방문 순서 출력도 완료한 것으로 표기하지 않는다.
